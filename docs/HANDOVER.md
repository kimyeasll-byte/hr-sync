# 프로젝트 진행 상황 핸드오버 (Project Handover)

## 1. 지금까지 완료된 작업 (오늘의 성과)
- **도메인 스토리텔링 (`docs/domain/`)**: 입사 온보딩 및 퇴사 권한 회수 프로세스(AS-IS/TO-BE), 용어집, 유저스토리, 인수 조건 도출 완료. (해결할 일과 사람이 직접 할 일 분리 완료)
- **UX 설계 (`docs/ux/`)**: 할 일 목록과 백그라운드 알림 기반의 사용자 동선(User Flow), 화면 상태 정의, 흑백 와이어프레임 설계 완료.
- **UI 디자인 (`docs/ui/`)**: 애플(Mac OS) 스타일의 차분한 전문가용 톤앤매너, 검정색 기준색, 4px 단위, 12px 둥글기, Lucide 아이콘 등 10가지 디자인 토큰 및 화면 HTML 확정. 커서(Cursor) 룰 세팅 완료.
- **기술 설계 준비**: 개발 전, 서비스 범위(할 일과 안 할 일) 5줄 요약 점검 완료.

## 2. 다음에 '이어서 하자'라고 할 때 시작할 작업
담당자(기획자)가 돌아오면, 개발 리드로서 **기술 스택과 아키텍처, 데이터 구조(Tech Architecture Workshop)** 결정을 시작한다.

**다음 단계 진행 원칙 (리뷰용)**:
- 개발 리드(AI)가 주도적으로 결정한 뒤 통보한다. (Next.js, Vercel, Supabase 기본값 사용 등. MVP 무료 범위 우선)
- 단, 5가지 예외(돈이 드는 결정, 되돌리기 힘든 결정, 개인정보/보안, 정책 부재, 서비스 범위 변경)에 해당할 때만 멈춰서 선택지를 주고 기획자에게 묻는다.

**이어서 바로 결정하고 문서화할 10가지 항목**:
1. 전체 구조 / 2. 로그인과 계정 / 3. 입력 데이터 처리 / 4. AI 호출 여부 / 5. 오래 걸리는 일(비동기) 처리 / 6. 데이터 구조(DB) / 7. 화면-데이터 연결 / 8. 에러 처리 / 9. 비용 상한선 / 10. 배포 및 환경 설정

**최종 산출물 타겟**: `docs/tech/` 폴더 생성 후 아키텍처 문서, ERD, 결정 기록(ADR), 한계점(비용/위험) 정리 후 최종 보고.
